# PDF And Image Recognition System For Structured Data Conversion

---

**Система распознавания PDF и изображений для преобразования данных в структурированный формат** — 
это веб-платформа для автоматического извлечения табличных данных из PDF-документов и 
изображений (JPG, PNG) с последующей конвертацией в структурированный формат (Excel `.xlsx`).

Данный проект выполнен в рамках курсовой работы за 2-ой год обучения на ФКН ПИ.
Проект поддерживает горизонтальное масштабирование вычислительных узлов (воркеров) и обеспечивает безопасное хранение данных через S3-совместимое объектное хранилище.

---

## Ключевые возможности

*   **Умное выделение таблиц:** Использование компьютерного зрения (OpenCV) для поиска границ таблиц и структурного анализа.
*   **Высокоточный OCR:** Интеграция с Tesseract 5.0+ для распознавания текста внутри ячеек таблиц.
*   **Асинхронная обработка:** Тяжелые задачи OCR вынесены в фоновые очереди (Celery + Redis), что значительно ускоряет работу.
*   **Горизонтальное масштабирование:** Архитектура позволяет запускать неограниченное количество изолированных воркеров для обработки пиковых нагрузок.
*   **Гибкая авторизация:** Поддержка JWT-токенов для пользователей и статических API-ключей (`X-API-Key`) для интеграции со сторонними системами.
*   **Email-уведомления:** Отправка писем пользователям при регистрации или смене пароля.
*   **Личный кабинет:** История всех распознаваний, генерация и пересоздание API-ключей.

## Переменные окружения (.env)

Все сервисы используют общий файл `.env` в корне репозитория. Его можно поделить на следующие группы настроек:

### 1. Хранилище MinIO
Система использует два типа подключений к MinIO:
*   **Внутреннее (`MINIO_*`):** Используется контейнерами внутри Docker-сети (`minio:9000`).
*   **Глобальное (`GLOBAL_MINIO_*`):** Используется для генерации публичных ссылок или доступа с хост-машины (требует указания реального IP сервера).
*   **Бакеты:** `UPLOADS_BUCKET_NAME` (исходники) и `RESULTS_BUCKET_NAME` (готовые `.xlsx` файлы).

### 2. База данных PostgreSQL
*   `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB` — учетные данные.
*   `SQLALCHEMY_DATABASE_URI` — строка подключения для SQLAlchemy (формат: `postgresql://user:pass@db:5432/dbname`).

### 3. Redis и Очереди
Redis разделен на логические базы данных для изоляции потоков:
*   **DB 0 (`CELERY_BROKER_URL`):** Брокер сообщений Celery.
*   **DB 1 (`CELERY_BACKEND_URL`):** Хранение результатов выполнения задач и статусов.
*   **DB 2 (`JWT_REDIS_BLACKLIST_URL`):** Хранение отозванных JWT-токенов (Logout).

### 4. Безопасность и Уведомления
*   `JWT_SECRET_KEY` — Секретный ключ для подписи JWT-токенов.
*   `MAIL_*` — Настройки SMTP-сервера для отправки уведомлений.
*   `TESSDATA_PREFIX` — Путь к словарям Tesseract внутри контейнера воркера (`/workspace/tessdata`).

## Инструкция по запуску и развертыванию


### Шаг 0: Клонирование репозитория
```bash
   git clone https://github.com/Restmine20/PDF-And-Image-Recognition-System-For-Structured-Data-Conversion
   cd PDF-And-Image-Recognition-System-For-Structured-Data-Conversion
   ```


### Шаг 1: Подготовка окружения
```bash
cp .env.example .env
nano .env # Заполните все необходимые данные с учетом подсказок из комментариев
```

### Шаг 2: Запуск системы

#### Вариант А: Полный запуск
Поднимает весь стек на одной машине. Подходит для разработки и небольших серверов.
```bash
docker compose --profile main --profile worker up --build -d
```

#### Вариант Б: Раздельный запуск
Вы можете запустить инфраструктуру на одном сервере, а воркеры вынести на другие машины.

**На главном сервере (Инфраструктура):**
```bash
docker compose --profile main up --build -d
```

**На вычислительных серверах (Только воркеры):**
*(Требуется настроенный `.env` с доступом к внешним Redis, MinIO и БД)*
```bash
docker compose --profile worker up --build -d
```

### Шаг 3: Масштабирование воркеров
Если очередь задач растет, вы можете динамически увеличить количество обработчиков без простоя системы:
```bash
# Запустить 4 дополнительных воркера
docker compose --profile worker up --build -d --scale worker=4
```

### Шаг 4: Доступ к сервисам
*   **Веб-интерфейс:** `http://<IP-сервера>` (или `https://recognitionsystem.ru` при настройке DNS в Caddyfile).
*   **API Backend:** `http://<IP-сервера>:8000`
*   **Консоль MinIO:** `http://<IP-сервера>:9001`

## Логика обработки данных (Worker Pipeline)

Когда пользователь загружает файл, Backend сохраняет его в MinIO и ставит задачу `process_file` в очередь Redis. Воркер подхватывает задачу и выполняет следующий пайплайн:

1.  **Инициация:** Воркер скачивает файл из `upload-bucket` во временную директорию (`TEMP_FOLDER`).
2.  **Маршрутизация:** Проверяется расширение файла.
    *   **Для PDF (`PDFProcessingModule`):**
        1. `TableExtractor.py`: Производится попытка извлечь таблицы с помощью информации, хранящейся в самом PDF файле (например, если он был получен конвертацией XLSX файла, то таблицы извлекутся без компьютерного зрения и OCR, что значительно повышает как точность, так и скорость работы).
        2. `ImageExtractor.py`: В случае, если в файле есть картинки, то они извлекаются, и по одной прогоняются через пайплайн для работы с изображениями.
          
    * **Для Изображений (`JPGProcessingModule`):**
        1.  `JPGPreprocessor.py`: Удаляет шум, корректирует перспективу и контрастность.
        2.  `TableExtractor.py`: Ищет контуры таблиц.
        3.  `ContentRecognizer.py`: Применяет OCR для каждой ячейки каждой таблицы.
3.  **Структурирование:** Данные записываются в объект `openpyxl.Workbook`.
4.  **Финализация:** Готовый `.xlsx` файл загружается в `results-bucket`, временные файлы удаляются с диска воркера, статус задачи в Redis обновляется на `SUCCESS`.

## Интеграция с внешними системами

Система поддерживает интеграцию со сторонними системами через заголовок **`X-API-Key`**.

1.  Авторизованный пользователь генерирует API-ключ в личном кабинете (`/api-key`).
2.  Ключ сохраняется в БД и привязывается к `user_id`.
3.  Внешняя система отправляет POST-запрос на эндпоинт загрузки с заголовком `X-API-Key: <ваш_ключ>`.
4.  Backend валидирует ключ, связывает документ с владельцем ключа и запускает стандартный процесс распознавания.
5.  Результат можно получить программно через API, используя тот же ключ.
