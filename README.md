# PDF-And-Image-Recognition-System-For-Structured-Data-Conversion

Система распознавания PDF и изображений для преобразования данных в структурированный формат.

## Состав проекта

Проект собирается одним `docker compose` из нескольких сервисов, которые
сгруппированы по профилям:

**Профиль `main`** — основная инфраструктура и пользовательская часть:
1) `frontend` — React-приложение (порт `8080` → `80` внутри контейнера)
2) `backend` — Flask-приложение (порт `8000`)
3) `db` — PostgreSQL 15
4) `redis` — Redis 7 (брокер задач и кэш, порт `6379`)
5) `minio` — S3-совместимое хранилище файлов (порт `9000`, консоль `9001`)

**Профиль `worker`** — фоновые воркеры, которые разбирают очередь и
  обрабатывают документы. Масштабируются независимо от основного стека.

Конфигурация всех сервисов берётся из общего `.env` в корне репозитория.

## Запуск

### Поднять всё сразу

```bash
docker compose --profile main --profile worker up --build
```


### Поднять только главный сервер (без воркеров)

```bash
docker compose --profile main up --build
```


### Поднять только воркеры

```bash
docker compose --profile worker up --build
```
Реализуют возможность горизонтального масштабирования

### Несколько воркеров

К профилю `worker` можно добавить флаг `--scale`, чтобы поднять сразу
несколько копий воркера:

```bash
docker compose --profile worker up --build --scale worker=4
```

Аналогично работает и при полном запуске:

```bash
docker compose --profile main --profile worker up --build --scale worker=4
```

### Остановить и удалить контейнеры

```bash
docker compose --profile main --profile worker down
```

`down` останавливает контейнеры и удаляет их вместе с
сетью. Профили указываются те же, что использовались при `up`.
